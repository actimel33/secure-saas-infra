# Контроли безопасности

Каждый контроль со схемы — со ссылкой на ресурс в коде и командой, которой
его можно проверить в работающей инфраструктуре.

Приведённые ответы команд сняты с развёрнутого стенда **24 сентября 2026
года**, регион `eu-central-1`. Идентификатор аккаунта и случайные суффиксы
имён заменены на `<account-id>` и `<suffix>`

## Управление доступом

| Контроль | Ресурс в коде | Чем доказывается |
|---|---|---|
| Пользователей IAM нет, доступ только через роли | [iam.tf](../terraform/iam.tf) — `aws_iam_role.app` с доверием к `ec2.amazonaws.com` | инстанс получает временные учётные данные, долгоживущего ключа не существует |
| Права выданы на конкретные ресурсы, а не на `*` | `data.aws_iam_policy_document.app` | один секрет, один бакет, один ключ; `s3:*` и `Resource: "*"` в политике нет |
| Вход на машины без SSH | политика `AmazonSSMManagedInstanceCore`, порт 22 не открыт ни в одной группе | оба инстанса на связи с Session Manager |
| Мастер-пароль базы не принадлежит человеку | [data.tf](../terraform/data.tf) — `manage_master_user_password = true` | секретом владеет сервис `rds`, ротация включена |
| Подключение к базе по временному токену IAM | `iam_database_authentication_enabled = true` | токен живёт 15 минут, отзывается снятием разрешения с роли |

**Проверка:**

```bash
aws ssm describe-instance-information --query 'InstanceInformationList[].{id:InstanceId,ping:PingStatus}' --output table
```

Обе машины — `Online`, то есть административный доступ идёт через Session
Manager, а не по SSH.

```bash
aws secretsmanager describe-secret --secret-id "<arn секрета из вывода db_secret_arn>" --query '{managedBy:OwningService,rotation:RotationEnabled,kms:KmsKeyId}'
```

Ответ: `managedBy: rds`, `rotation: true`, ключ — наш собственный, а не выданный AWS по умолчанию. Значение
пароля не запрашивается ни здесь, ни где-либо ещё в проекте.

## Сеть

| Контроль | Ресурс в коде | Чем доказывается |
|---|---|---|
| Три зоны доверия | [vpc.tf](../terraform/vpc.tf) — `aws_subnet.public`, `.app`, `.data` | публичные адреса только у балансировщика и NAT |
| У инстансов нет публичных адресов | [app.tf](../terraform/app.tf) — `associate_public_ip_address = false` | `publicIp: None` у обеих машин |
| У зоны данных нет выхода в интернет | `aws_route_table.data` без маршрута `0.0.0.0/0` | выгрузить базу наружу с самого сервера базы невозможно |
| База недоступна из интернета | `publicly_accessible = false`, группа `db` пускает только группу `app` | имя базы резолвится в приватный адрес `10.60.21.x`, соединение снаружи не устанавливается |
| Правила ссылаются на группы, а не на адреса | [security-groups.tf](../terraform/security-groups.tf) — `referenced_security_group_id` | новый инстанс попадает под правило без правки диапазонов |
| Единственный вход — балансировщик | группа `app` принимает трафик только от группы `alb` | прямое обращение к инстансу невозможно даже изнутри VPC |

**Проверка отказом**:

```bash
timeout 8 bash -c 'cat < /dev/null > /dev/tcp/<адрес базы>/5432' && echo открыто || echo закрыто
```

Ответ: `закрыто`. При этом DNS-имя базы резолвится в `10.60.21.19` —
приватный адрес, маршрута к которому из интернета нет.

## Шифрование

| Контроль | Ресурс в коде | Чем доказывается |
|---|---|---|
| Собственный ключ KMS с ротацией | [data.tf](../terraform/data.tf) — `aws_kms_key.main` | ротация включена, период 365 дней |
| База зашифрована | `storage_encrypted = true`, `kms_key_id` | `encrypted: True` |
| Диски инстансов зашифрованы | [app.tf](../terraform/app.tf) — `root_block_device.encrypted` | оба тома `gp3`, `encrypted: true`, ключ — наш собственный |
| Файлы клиентов зашифрованы | `aws_s3_bucket_server_side_encryption_configuration.files` | `SSEAlgorithm: aws:kms` с нашим ключом |
| Журналы зашифрованы | лог-группы с `kms_key_id`, CloudTrail с `kms_key_id` | обе группы `/secure-saas/dev/*` шифруются нашим ключом |
| Обращение к хранилищу только по TLS | политика бакета с `Deny` при `aws:SecureTransport = false` | попытка по HTTP отвергается явным запретом |

**Проверка:**

```bash
aws s3api list-objects-v2 --bucket secure-saas-dev-files-<suffix> --endpoint-url http://s3.eu-central-1.amazonaws.com
```

Ответ: `AccessDenied ... with an explicit deny in a resource-based policy`.
Запрет сработал именно на незашифрованном канале — те же права по HTTPS
работают.

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://secure-saas-dev-files-<suffix>.s3.eu-central-1.amazonaws.com/
```

Ответ: `403`. Публичного доступа нет, все четыре флага блокировки включены.

## Логирование и обнаружение

| Контроль | Ресурс в коде | Чем доказывается |
|---|---|---|
| Журнал вызовов API по всем регионам | [logging.tf](../terraform/logging.tf) — `aws_cloudtrail.main` | `IsMultiRegionTrail: true` |
| Журнал защищён от правки задним числом | `enable_log_file_validation = true` | `LogFileValidationEnabled: true` |
| События объектов в бакете клиентов | `advanced_event_selector` на `AWS::S3::Object` | чтение и запись каждого файла попадает в журнал |
| Журнал доступен для поиска сразу | `cloud_watch_logs_group_arn` + роль доставки | `LatestCloudWatchLogsDeliveryError: null` |
| Метаданные сетевых соединений | `aws_flow_log.vpc` | статус `ACTIVE`, тип `ALL` |
| Журнал обращений к приложению | журналы доступа ALB в бакет логов | `access_logs.s3.enabled: true` |
| Срок хранения задан явно | `retention_in_days = var.log_retention_days` | 90 дней вместо «вечно» по умолчанию |
| Оповещения о событиях безопасности | [monitoring.tf](../terraform/monitoring.tf) — четыре правила EventBridge → SNS | вход под root, правка групп безопасности, остановка журнала, создание пользователя IAM |

**Проверка:**

```bash
aws cloudtrail get-trail-status --name secure-saas-dev-trail --query '{logging:IsLogging,s3Error:LatestDeliveryError,cwError:LatestCloudWatchLogsDeliveryError}'
```

Ответ: `logging: true`, обе ошибки `null` — журнал пишется в оба назначения.

## Резервное копирование

| Контроль | Ресурс в коде | Чем доказывается |
|---|---|---|
| Автоматические копии базы | `backup_retention_period = 7` | `backupDays: 7`, ноль запрещён валидацией переменной |
| Теги переносятся на снимки | `copy_tags_to_snapshot = true` | снимок сохраняет принадлежность к проекту |
| Версии файлов клиентов | `aws_s3_bucket_versioning.files` | `Status: Enabled` — перезапись и удаление обратимы |
| Обновления безопасности движка | `auto_minor_version_upgrade = true` | `autoMinor: True`, PostgreSQL 18.3 |

## Соответствие критериям SOC 2

| Контроль | Критерий Trust Services |
|---|---|
| Роли вместо пользователей, доступ по наименьшим привилегиям | CC6.1 — логический доступ к ресурсам ограничен |
| Session Manager вместо SSH, весь доступ в журнале | CC6.1, CC6.6 — административный доступ контролируется и фиксируется |
| Сегментация на три зоны, база без выхода наружу | CC6.6 — граница системы защищена |
| Шифрование данных в покое и в канале | CC6.7 — передача и хранение защищены |
| CloudTrail с проверкой подписи, flow logs, журналы ALB | CC7.2 — система отслеживается, события фиксируются |
| Оповещения EventBridge о критичных событиях | CC7.3 — события оцениваются, о сбоях сообщается |
| Автоматические копии и версионирование | A1.2 — восстановление после отказа |
| Проверка кода сканером в CI | CC8.1 — изменения проходят контроль |

## Контроли со схемы, не реализованные в коде

| Контроль | Причина | Компенсация |
|---|---|---|
| TLS на балансировщике | у проекта нет домена, без домена сертификат ACM не выдать | переменная `certificate_arn`: при её заполнении создаётся слушатель HTTPS с политикой TLS 1.2+, а порт 80 переходит в редирект |
| WAF | около 5 долларов в месяц плюс плата за правило | переменная `enable_waf`, три управляемых набора правил готовы в коде |
| GuardDuty и AWS Config | тарифицируются постоянно, кредиты аккаунта ограничены | переменные `enable_guardduty` и `enable_config`, восемь правил Config описаны в коде |
| Реплика базы во второй зоне | удваивает стоимость базы | переменная `db_multi_az`, группа подсетей уже охватывает две зоны |
| Интерфейсные VPC-эндпоинты | оплата за каждый час существования каждого эндпоинта | переменная `enable_interface_endpoints`; пока обращения к сервисам идут через NAT |
| Защита базы от удаления | учебный стенд многократно сносится | переменная `db_deletion_protection`, для production значение `true` |

Состояние всех переключателей в конкретном развёртывании видно в выводе
`enabled_guardrails` — чтобы отчёт о соответствии не расходился с тем, что
работало на самом деле.
